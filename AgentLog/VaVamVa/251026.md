## 2. InteractableComponent 대폭 리팩토링

### 상태 관리 단순화

#### 변경 전
```cpp
enum class EInteractableState : uint8
{
    Default,
    OutOfBound = 1 << 1,
    InRange = 1 << 2,
    UnFocused = 1 << 3,  // 바라본 상태에서 벗어남
    Focused = 1 << 4,    // 바라보는 상태
    Interacting = 1 << 5 // 상호작용 중
};
```

#### 변경 후
```cpp
enum class EInteractableState : uint8
{
    Default,
    OutOfBound = 1 << 1,
    InRange = 1 << 2,
    Focused = 1 << 3,    // 순서 변경 및 단순화
    UnFocused = 1 << 4   // Interacting 상태 제거
};
```

**제거 이유:**
- `Interacting` 상태는 실제로 불필요한 중간 상태였음
- 상호작용은 이벤트로 처리하면 충분하므로 별도 상태 불필요

### Delegate 개선

#### 변경 전
```cpp
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FOnChangeState, APlayerController*, playerController, const EInteractableState&, newInteractableState);
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnRequestInteraction, APawn*, player);
```

#### 변경 후
```cpp
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnClientInteraction, APlayerController*, playerController);
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnMultiInteraction, APawn*, player);
```

**개선 사항:**
- 상태 변경을 추적하지 않고 **상호작용 이벤트만 전달**
- 클라이언트 전용 상호작용과 멀티플레이 상호작용 명확히 분리

### 메서드 통합 및 단순화

#### 변경 전
```cpp
void TryDeactivateInteractable(APlayerController* playerController);
void TryActivateInteractable(APlayerController* playerController);
void OutOfInteractableRange(APlayerController* Player);
void InInteractableRange(APlayerController* Player);
```

#### 변경 후
```cpp
void TryChangeState(APlayerController* playerController, EInteractableState newState);
```

**통합 효과:**
- 4개의 상태 변경 함수를 **1개로 통합**
- Switch 문으로 명확한 상태 전이 로직 구현
- 중복 코드 제거 및 가독성 향상

### TryChangeState 구현 로직

```cpp
void UInteractableComponent::TryChangeState(APlayerController* playerController, EInteractableState newState)
{
    if (!LIKELY(IsValid(playerController))) {return;}
    if (!playerController->IsLocalController()) {return;}
    if (clientState == EInteractableState::Default) {return;}

    switch (newState)
    {
    case EInteractableState::Default:
        clientState = EInteractableState::Default;
        break;

    case EInteractableState::UnFocused:
    case EInteractableState::InRange:
        {
            if (!IsValid(playerInRange)) {return TryChangeState(playerController, EInteractableState::OutOfBound);}
            UInteractionComponent* interactionComp = playerInRange->FindComponentByTag<UInteractionComponent>("Interaction");
            if (IsValid(interactionComp))
            {
                clientState = EInteractableState::InRange;
            }
            if (interactionComp->GetFocusedActor() != GetOwner()) {break;}
        }

    case EInteractableState::Focused:
        {
            if (!EnumHasAnyFlags(clientState, EInteractableState::InRange)) {return;}
            clientState = EInteractableState::Focused;
            break;
        }

    case EInteractableState::OutOfBound:
        {
            playerInRange = nullptr;
            clientState = EInteractableState::OutOfBound;
            break;
        }
    }

    UpdateVisuals(playerController);
}
```

### 상호작용 로직 개선

#### 변경 전
```cpp
void UInteractableComponent::TryInteract(APlayerController* playerController)
{
    clientState = EInteractableState::Interacting;
    onChangeState.Broadcast(playerController, EInteractableState::Interacting);
    UpdateVisuals(playerController);
    PlayEffects();
}
```

#### 변경 후
```cpp
void UInteractableComponent::TryInteract(APlayerController* playerController)
{
    if (!LIKELY(IsValid(playerController))) {return;}
    if (!playerController->IsLocalController()) {return;}
    if (clientState != EInteractableState::Focused) {return;}

    if (OnClientInteraction.IsBound())
    {
        OnClientInteraction.Broadcast(playerController);
        PlayEffects(true);
        FinishInteracting(playerController, true);
    }
}
```

**개선 사항:**
- Delegate가 바인딩되어 있을 때만 실행
- 성공 여부를 명확히 전달 (`bSuccess` 파라미터)
- 상호작용 완료 후 자동으로 상태 정리

### 멀티캐스트 상호작용

```cpp
void UInteractableComponent::Multicast_TryInteract_Implementation(APawn* player)
{
    if (!IsValid(player) || !feedbackSettings.IsNetworkOn()) {return;}
    if (OnMultiInteraction.IsBound())
    {
        OnMultiInteraction.Broadcast(player);
        PlayEffects(true);
        if (APlayerController* pc = player->GetController<APlayerController>())
        {
            FinishInteracting(pc, true);
        }
    }
}
```

### FinishInteracting 개선

#### 변경 전
```cpp
void FinishInteracting(APlayerController* Player, const EInteractableState& newState);
```

#### 변경 후
```cpp
void FinishInteracting(APlayerController* playerController, bool bSuccess)
{
    if (!LIKELY(IsValid(playerController))) {return;}
    if (!playerController->IsLocalController()) {return;}

    if (bSuccess)
    {
        TryChangeState(playerController, EInteractableState::OutOfBound);
        return;
    }
    TryChangeState(playerController, EInteractableState::InRange);
}
```

**개선 사항:**
- 새로운 상태를 직접 받는 대신 **성공 여부만 전달**
- 성공 시 OutOfBound, 실패 시 InRange로 자동 전환
- 로직이 명확하고 예측 가능

### 명명 개선

| 변경 전 | 변경 후 | 이유 |
|--------|--------|------|
| `CanPossess()` | `IsMultiPlayable()` | 멀티플레이 가능 여부를 명확히 표현 |
| `outlinedMeshComponent` | `ownerMeshComponent` | 실제 기능을 더 정확히 표현 |
| `onChangeState` | `OnClientInteraction` | 이벤트 명명 규칙 준수 및 의미 명확화 |
| `onRequestInteraction` | `OnMultiInteraction` | 멀티플레이 상호작용 명확히 표현 |

### 불필요한 멤버 제거

```cpp
// 제거됨
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Server")
TArray<APawn*> possessingPlayers;
```

**제거 이유:**
- 실제로 사용되지 않는 멤버 변수
- 멀티플레이 관리는 별도 시스템에서 처리

## 주요 학습 포인트

### UDeveloperSettings의 장점
1. **자동 설정 관리**: Config 파일에 자동 저장/로드
2. **에디터 통합**: Project Settings에 자동 표시
3. **싱글톤 패턴**: `GetDefault<T>()` 한 줄로 접근

### 상태 관리 베스트 프랙티스
1. **최소한의 상태**: 불필요한 상태는 제거
2. **명확한 전이**: Switch 문으로 전이 로직 명확화
3. **이벤트 기반**: 상태 변경보다 이벤트 전달 우선

### Component 기반 설계
1. **책임 분리**: 각 컴포넌트는 명확한 역할
2. **재사용성**: 다른 Actor에도 쉽게 적용
3. **테스트 용이성**: 독립적으로 테스트 가능
